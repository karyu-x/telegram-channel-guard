# Telegram Channel Guard v4.1

Апгрейд v4 для более надёжной фильтрации фотографий и Telegram-альбомов.

## Что исправлено

### 1. Полноразмерные фото источника

Для `photo` Telethon теперь сначала скачивает полноценную фотографию канала,
а thumbnail используется только как fallback.

Это устраняет ситуацию, когда в кэше был fingerprint маленького thumbnail,
а в группе сравнивалась большая повторно загруженная фотография.

### 2. Три perceptual hash

Фото сравниваются одновременно через:

- dHash
- aHash
- pHash

Используются несколько небольших center-crop вариантов и mirror.

### 3. Альбомы Telegram

Если пользователь отправил 4 фотографии одним album/media_group и хотя бы
одна фотография совпала с материалом канала A:

- найденная фотография удаляется;
- уже пришедшие элементы этого же media_group удаляются;
- последующие элементы того же album удаляются сразу.

То есть один запрещённый элемент блокирует весь альбом.

## Остальная защита сохранилась

- Forward из `@ibragimmansurov_blog`
- `@ibragimmansurov_blog`
- `@manager_ibragimmansurov`
- соответствующие t.me / telegram.me / tg:// ссылки
- скрытые text_link
- exact/fuzzy копии текста
- видео и video note по Telegram thumbnail

Другие `t.me` ссылки не блокируются.

## Railway Variables

Остаются те же:

```env
BOT_TOKEN=...
API_ID=...
API_HASH=...
TELETHON_SESSION=...
```

Новых Variables нет.

## Railway Start Command

```bash
python bot.py
```

## После deploy

Сначала:

```text
/status
```

Теперь статус отдельно показывает:

```text
Кэш фото: ...
Кэш видео: ...
Кэш медиа всего: ...
```

Если ты только что обновил алгоритм, желательно выполнить:

```text
/rescan
```

чтобы весь source cache заново заполнился fingerprints v4.1.

## Главный тест

1. Дождись, когда `/status` покажет ненулевой `Кэш фото`.
2. Возьми фотографию из старого поста `@ibragimmansurov_blog`.
3. Скачай её.
4. Отправь в группу самостоятельно, не Forward.
5. Потом попробуй отправить её как часть альбома из 3-4 фотографий.

При совпадении весь album должен исчезнуть.
