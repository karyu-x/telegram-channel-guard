# Telegram Channel Guard v3

Бот без базы данных для защиты группы от контента из конкретного источника:

`@ibragimmansurov_blog`

## Что удаляется

1. Настоящие Telegram Forward из `@ibragimmansurov_blog`.
2. Сообщения, содержащие только конкретные запрещённые Telegram username/link:
   - `@ibragimmansurov_blog`
   - `@manager_ibragimmansurov`
   - соответствующие `t.me/...`, `telegram.me/...`, `tg://...`
   - скрытые text_link на эти же username.
3. Точные и почти точные текстовые копии постов источника.
4. Фото из источника, если его скачали и загрузили заново.
5. Обычные видео, круглые video message и GIF — по визуальному thumbnail/кадру.

Другие `t.me` ссылки бот НЕ удаляет.

## Как работает media matching

Бот читает публичную Telegram preview-страницу канала и получает preview
фото/видео. Для изображений строится perceptual fingerprint:

- dHash;
- aHash;
- несколько небольших center-crop вариантов.

В группе:

- фото сравнивается по самому изображению;
- обычное видео — по thumbnail/cover;
- video note (круглое видео) — по thumbnail;
- GIF/animation — по thumbnail;
- фото/видео, отправленные как document — по изображению или thumbnail.

Это рассчитано на случай, когда файл скачали из канала и заново загрузили в группу.

## Важные ограничения

- Сильно обрезанное, зеркальное или существенно отредактированное изображение
  может не совпасть.
- Для видео сравнивается preview-кадр, а не весь видеоряд. Если Telegram выберет
  совершенно другой thumbnail после сильного редактирования видео, совпадение
  может не сработать.
- Если Telegram изменит HTML публичной preview-страницы, обновление кэша
  источника может временно перестать работать. Forward/link-фильтр останется.
- Perceptual matching может удалить то же самое изображение/видео, даже если
  пользователь получил его не напрямую из канала A: бот определяет контент,
  а не намерение пользователя.

## Railway

Нужна только переменная:

```env
BOT_TOKEN=...
```

Start Command:

```bash
python bot.py
```

Volume и DB_PATH не нужны.

После deploy выполни в группе:

```text
/status
```

Нормальный статус будет содержать примерно:

```text
Кэш текста: 100
Кэш медиа: 60
```

Если `Кэш медиа: 0`, открой Railway Deploy Logs и проверь строку
`Source bootstrap failed`.
